## What's new: security fixes

v1.0.1 fixes the findings from the security review of v1.0 (PRs #75–#78). It has no new features and no rule changes. The build number goes from 1 to 2, so an installed v1.0 helper is replaced by the new one on the first launch.

**Admin helper**
- **Restore can no longer put back a different file (finding 5).** Your Trash belongs to you, so before this fix another program running as you could swap a trashed item for its own file. Restoring would then put that file back into a system folder with root ownership. The helper now records exactly which file it moved, by device and inode. It restores only that same file, never follows a symbolic link, never overwrites anything, and sets owner and permissions without following links. Emptying through the helper checks the same thing.
- **Moving to the Trash can't be redirected (finding 4).** The helper opens your Trash without following links and checks that it's a real folder owned by you. If the Trash is missing, it creates one owned by you, readable only by you. It never overwrites an item already there; a name clash gets the next free name.
- **The helper's Trash record is private (finding 7).** It is now readable only by root (mode 600), not by every account on the Mac.

**Cleanup in the app**
- **Permanent deletes can't be redirected mid-delete (finding 1).** Cache and log cleanup and Empty Trash now use the same delete code as the helper. The app confirms the item is still the one you reviewed, then deletes by folder handle without ever following a link. Swapping a folder for a link partway through can't send the delete somewhere else.
- **A cache folder that is a link is skipped, not followed (finding 3).** If a folder a rule cleans is a symbolic link, for example a cache folder pointing at Downloads, it is skipped and listed with the reason instead of being cleaned.
- **A folder holding a photo or media library is never removed (finding 12).** Before, only the library itself was protected. Now any folder that contains a `.photoslibrary` or similar library is skipped too, in the app and in the helper.
- **Two copies of the same app (finding 6).** If another copy with the same bundle ID is installed, the uninstaller keeps the related files and says "another copy of this app is installed (path)".
- **Update checks are size-limited (finding 8).** An update feed larger than 5 MB is refused instead of loaded into memory.

**Tooling**
- **CI runs with a read-only token (finding 9).** The checkout step is pinned to a reviewed commit and doesn't keep the token.
- **The canary check fails when it should (finding 11).** `canary.sh check` now fails (exit 1) when a ticked canary survives or anything else in the zones disappears. A new `canary.sh check-restored` step confirms a restored item came back as the same file, owned root:wheel, mode 644.

**Known limitation:** the new helper won't restore items the v1.0 helper moved to the Trash, because v1.0 didn't record which file it moved. Those items show the reason in TidyMyMac. Move them back yourself if you need them (`sudo mv` back, then `sudo chown root:wheel`). They can still be emptied through TidyMyMac.

Not fixed (judged not worth it): finding 2 (a hand-edited run log could offer a misleading Restore; low impact, possible follow-up) and finding 10 (a historical research script in `docs/planning`).
